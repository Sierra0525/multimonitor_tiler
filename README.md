# MultiMonitorTiler

指定したウィンドウをキャプチャして、複数モニターにまたがる**表示専用のミラー**として拡大表示する Windows 用 CLI ツールです。対象ウィンドウ自身のリサイズや、対象アプリの実行ファイル・互換設定への変更は一切行いません。

## この設計を選んだ理由

複数モニターにまたがってウィンドウを「拡大表示」するとき、モニター境界で映像がズレる原因は主に2つあります。

1. Windows のスケーリング設定(100%/125%など)がモニター間で異なる
2. モニター実物の**物理的な画素密度(実DPI)** がわずかに異なる(例: 同じ解像度でもパネルサイズが違う、個体差がある等)

2番目の「実DPIそのものの違い」は Windows の API からは直接取得できず、機械的に自動補正することはできません。そこで本ツールは、対象アプリには一切手を加えず、次の方式を採ります。

- **DWM Thumbnail API** (`DwmRegisterThumbnail`) で対象ウィンドウの内容を GPU コンポジタ側で直接キャプチャし、各モニターを覆う専用の透明なホストウィンドウ上に描画します。これは Windows のタスクバー プレビューと同じ仕組みで、ピクセルコピーやポーリングが発生しないため低遅延です。対象ウィンドウの内容が更新されると自動的に反映されます。
- 各モニターへ表示する範囲(クロップ位置・拡大率)は、まずモニターの物理配置比率から機械的に初期値を計算し、そのうえで**実行中にホットキーでライブに微調整**できます。実DPI差による境界のズレは、この手動調整で解消します。
- 一度調整した値はモニターの組み合わせ(接続されているモニターの識別名の集合)ごとに保存され、次回同じモニター構成で `mirror` を実行したときに自動的に読み込まれます。

この方式は**表示専用**です。拡大表示された側の画面はマウス/キーボード操作を受け付けません(元のウィンドウは元の場所でそのまま操作してください)。

## 必要環境

- Windows 10 (1703以降) / Windows 11
- .NET 8 SDK (`dotnet build` に使用。実行だけなら発行した exe と .NET 8 デスクトップランタイムのみで可)
- 対象ウィンドウが管理者権限で動いている場合、本ツールも管理者として実行してください

## ビルド

```powershell
cd src\MultiMonitorTiler
dotnet build -c Release
```

成果物: `src\MultiMonitorTiler\bin\Release\net8.0-windows\MultiMonitorTiler.exe`

単一 exe として発行する場合:

```powershell
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

## 使い方

### 1. モニター一覧を確認

```powershell
MultiMonitorTiler.exe list-monitors
```

番号・位置・解像度・Windowsスケール(%)・プライマリかどうかが表示されます。ここでの「スケール」は OS の100%/125%設定であり、モニター実物の画素密度の違いとは別物です。この番号を `mirror` の `--monitors` に使います。

### 2. 対象ウィンドウを確認

```powershell
MultiMonitorTiler.exe list-windows
```

### 3. ミラー表示を開始

```powershell
MultiMonitorTiler.exe mirror --window "メモ帳" --monitors 1,2,3
```

- `--window` にはタイトルの一部を指定します(部分一致・大文字小文字無視)。
- `--monitors` は `list-monitors` の番号のカンマ区切り、または `all`。

実行すると、選択した各モニターがそのウィンドウの内容で覆われ、あわせて小さな「コントロールパネル」ウィンドウが開きます。境界がズレている場合は、コントロールパネルにフォーカスした状態で以下のホットキーを使ってください。

| キー | 動作 |
|---|---|
| `Tab` | 調整対象モニターを切替 |
| `↑ ↓ ← →` | 表示位置をパン(`Shift` 併用で大きく移動) |
| `+` / `-` | ズーム(`Shift` 併用で大きく変化) |
| `R` | 現在のモニターの補正をリセット |
| `S` | 補正値を今すぐ保存 |
| `Esc` | 終了(自動保存) |

隣接するモニターの境界にある基準となる直線やアイコン格子などを目印に、ズレがなくなるまで各モニターのズーム/位置を調整してください。調整値は保存され、同じモニターの組み合わせであれば次回以降も自動適用されます。

## 制限事項

- 表示専用です。拡大表示された側でのマウス/キーボード操作はできません。
- 動画のフルスクリーン専有モードや DRM 保護コンテンツは、DWM Thumbnail 自体がキャプチャできない場合があります(通常のデスクトップアプリ・ブラウザは問題ありません)。
- 対象ウィンドウが最小化されている間はミラー内容が更新されません(`mirror` 開始時に最小化されていれば自動的に復元します)。
- 対象ウィンドウがリサイズされた場合、次にホットキーで調整するまでクロップ位置がずれることがあります。

## プロジェクト構成

```
src/MultiMonitorTiler/
  Program.cs               CLI エントリポイント・コマンド処理
  Native.cs                 Win32 / DWM Thumbnail API の P/Invoke 宣言
  MonitorService.cs          モニター列挙・外接矩形計算
  WindowService.cs           ウィンドウ列挙
  MirrorController.cs        DWM サムネイルのライフサイクル管理・適用
  MonitorHostForm.cs         モニターを覆う表示専用ホストウィンドウ
  ControlPanelForm.cs        ホットキー受付用のコントロールパネル
  MonitorCalibration.cs      モニターごとのズーム/位置補正モデル
  CalibrationStore.cs        補正値の保存・読み込み(モニター組み合わせ単位)
  SourceRectCalculator.cs    モニター配置比率+補正値からクロップ矩形を計算
  app.manifest               本ツール自身を Per-Monitor-V2 DPI aware に設定
```
